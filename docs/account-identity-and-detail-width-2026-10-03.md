# 账号去重与明细窗口宽度修正

## 原因与修改

- Token 会因授权和刷新而变化，不能只用 Token 相等判断同一账号。ChatGPT 旧授权可能未单独存储 accountID，现从已有 access token 的账号 claim 补全；不同 workspace ID 仍按不同额度账号处理。
- 智谱先前仅隔离网页登录空间，没有账号去重。现读取官方页面 Vue store 中 customerNumber，保存为 customer:编号，在根账号模型统一比较。新增登录等待客户身份确认；重复条目不连接、不展示，并提示已有名称。旧账号身份延迟到达时，按保存顺序保留原条目，重复条目取消展示。重复草稿保留，用户可重试或移除。
- 网页桥接只转发客户编号及额度白名单，未转发 Cookie、Authorization 或 Token。客户编号若晚于额度响应，最多等待 8 秒，不另发网络请求；未确认身份时登录窗保持打开。
- 后续补齐 DeepSeek：解析可选 `user_id` / `id`（字符串或 Int64，两个字段冲突拒绝），以 `user:` 身份优先，完整联系方式作为身份别名。比较新旧资料的身份集合；双方稳定 ID 明确不同时优先按 ID 判定。已知身份即使旧 Token 被删除，也继续保护原条目；旧资料只提供邮箱、新资料提供 ID 与同一邮箱时仍能识别重复。
- DeepSeek、ChatGPT 身份无法比较时，暂不保存多账号授权；不会因 Token 不同而直接认作不同账号。DeepSeek 未知旧身份的当前条目仍允许有效重新授权恢复，已知身份则禁止无法验证的覆盖。不使用昵称、余额或脱敏号码合并。
- ChatGPT 将账号 ID 独立保存到 AccountProfiles，旧授权开始刷新前迁移身份，删除过期授权不再丢失条目身份；重登与重复判断也检查无授权但已知身份的条目。
- DeepSeek 官方公开页面读取返回 429，未继续请求；可选 ID 字段兼容通过构造响应测试，尚未确认真实服务是否返回这些字段。不能把测试样本当作官方接口保证。
- 主窗口按 enabled 平台数计算宽度，卡片按可见账号数绘制，隐藏登录条目造成外侧空白。改为 detailSnapshots.count，并在首次显示和重新展开时重新发布实际尺寸。

## 验证范围

新增回归覆盖：旧 ChatGPT JWT 身份、不同 workspace、两张卡片重新展开纠正旧三列宽度、智谱相同／不同客户编号、等待身份、后台账号身份持久化、旧账号身份晚到、重复条目后续缺身份刷新，以及网页脚本延迟身份和凭据过滤。

初次修正 `swift test`：318 项，1 项联网测试跳过，0 失败。补齐三平台身份及过期授权保护后的完整 `swift test`：334 项，1 项联网测试跳过，0 失败。只读复审未发现新的实质性问题。

本轮未进行真实账号重新授权，也未启动第二个生产应用。真实平台登录流程仍需安装后确认；读取 DeepSeek 当前资料结构的单次只读尝试返回 429，未重试或据此推测身份字段。
