# 账号生命周期与运行模型改造

本轮落实产品评估中的第一条技术主线，未新增功能平台或改变界面排版，尚未发布新版本。

## 实际结构

- IslandModel：账号目录、选择、应用状态、账号删除与监测编排。
- IslandModel+Accounts：显示账号、需监测账号集合，以及按 AccountReference 索引的固定运行实例。
- AccountRuntime：不可变账号引用，独立的数据、请求版本、认证、WebKit 会话、轮询和重置补查。
- AccountRuntime+Snapshot：从账号数据生成现有展示快照。
- IslandModel+Compatibility：保留平台式读取接口，全部代理到对应账号，供旧视图逐步迁移；没有第二份数据。

选择账号不再缓存、复制或接管另一实例。已移除实例永久失效，legacy ID 重新添加时不会让旧实例继续发请求。新账号初始没有另一账号的额度。

## 修复与测试证据

| 场景 | 原失败 | 当前行为 |
| --- | --- | --- |
| 删除最后一个非默认账号 | 重置目录后事件携带 legacy ID，真实账号配置与预约残留 | 以删除前准确 ID 清理 |
| 切换账号 | 原运行实例被替换，缓存搬运并额外刷新 | 实例稳定，保留数据，无额外请求 |
| 隐藏且无用途的当前账号 | 仍启动后台请求 | 仅监测显示、菜单栏或提醒所需账号 |
| 隐藏提醒账号网络恢复 | 只补查当前账号 | 遍历所有需监测账号 |
| 凭据删除失败 | 原实例被提前销毁 | 保留账号和缓存，报告失败 |
| 提醒总开关变化 | 依赖菜单栏控制器协调后台生命周期 | 主模型直接观察设置并调整监测 |
| 删除后重新添加 legacy 账号 | 旧实例可再次读取新授权 | 旧实例失效，不发请求 |

独立审阅未发现重大回归，并指出隐藏时仍可能发起排队资料请求或慢请求之后的补查。两项已补充失败测试并修复；暂停后仍保存已在途结果，但不继续发起这些后续请求。

新回归均在实现前观察到对应失败。更新一项旧提醒测试的准备步骤：显式为新账号提供自己的数据，保留去重断言，并验证新账号初始为空。
