# AIUsageIsland 公开发布实施拆分

> 本文是实施评估和任务拆分，不是直接修改产品的指令。各变更包开始前，按 superpowers:executing-plans 将该包细化为实现步骤；凭据、默认值迁移和异步存储需先确定接口及失败处理。本轮仅新增本文。

**Goal:** 将公开发布路线图落到相互独立、可验证的变更包。

**Architecture:** 保留 AccountRuntime、平台适配器和统一快照。先统一安装迁移判定，再改善入口与恢复状态；凭据存储和历史存储分别修改。布局调整不改变数据口径和持久化标识。

**Tech Stack:** Swift 6 / SwiftPM、macOS 14+、SwiftUI / AppKit、Security / Keychain、WebKit。

**Spec:** [公开发布改进计划](2026-10-07-public-release-improvements.md)。

## 全局约束

- 最低系统保持 macOS 14；首发架构建议 Apple Silicon，分发渠道仍待产品决定。
- 不读取其他客户端凭据；不更改 bundle identifier、账号 UUID、通知标识和历史路径。
- 显式旧设置优先；无法确定是否新安装时保留旧行为。
- 不把缺失值当零、不把百分比换算为 Token、不把公告当个人额度到账。
- 固定正式签名身份后验收 Keychain；凭据写入并读回确认前不删旧文件。
- 暂停新增平台、聊天、云同步和统一账单；D2 与商店分支单列。
- UI 改动用实际交互和渲染验收；行为、迁移及并发变更使用针对性测试。

## 三处需先完成的详细设计

### 安装和偏好迁移

- [ ] 盘点 UserDefaults 历史标识与账号存储的存在证据，明确新安装、已识别旧安装、模糊状态的判断规则。
- [ ] 在启动流程创建默认账号状态、执行任何偏好持久化之前捕获安装证据；IslandModel 初始化会构造默认 AccountProfiles，持久化由后续 persistProfiles 等路径执行，不能把默认内存账号状态作为旧安装证据。
- [ ] 新增版本化迁移标记；菜单栏默认、公告默认和引导完成复用同一判定，分别尊重已有显式值。
- [ ] 对没有显式菜单栏键的旧安装保留原行为；手动再次打开引导不重置安装状态。

### 凭据存储

- [ ] 将读取结果分为不存在、拒绝/锁定、损坏和存储失败；启动恢复及重复账号检测均使用同一接口。
- [ ] 列出迁移状态及重试路径：旧文件存在、Keychain 已写未删旧文件、读回失败、删除失败、迁移完成。
- [ ] Keychain 以应用、平台、账号 UUID 定位，保留历史目录作为数据路径，不将凭据与目录职责绑定。
- [ ] 明确刷新轮换成功但保存失败的内存状态与恢复动作；删除和断开账号核对最后一个账号的特殊分支以及 WebKit 清理路径。
- [ ] 回退仅使用兼容新存储的修复版；不承诺旧二进制直接读取新凭据。

### 历史存储

- [ ] 展示 Store 保持主线程，串行执行器负责读取、编码和写盘；读取完成不得覆盖已经刷新的内存数据。
- [ ] 同一次额度刷新先生成完整内存结果再提交，避免按多个指标重复全量编码写盘。
- [ ] 每账号设置生命周期代次或失效标识；删除必须先阻止旧写入，再执行目录清理，不能只取消 Task。
- [ ] 区分网络错误与持久化错误；磁盘失败保留当前数据和可见未保存状态。
- [ ] 确定退出等待上限与未落盘策略，保留现有 JSON 格式及路径。

## Review Focus

1. 新默认值覆盖旧偏好：由包 1 和包 7 验证明确关闭、缺键旧安装、模糊状态及重复迁移。
2. Keychain 错误导致账号消失或丢唯一令牌：由包 5 验证启动读取、轮换保存、读回和删除故障。
3. 删除账号后历史复活：由包 9 用可控迟到读写验证，覆盖加载、排队、写入中和删除后返回。
4. 授权、429 与取消互相覆盖：由包 3 和包 5 验证冷却优先及轮换后的持久化语义，复用已有竞态测试。
5. 多屏/全屏/睡眠和系统通知抑制：由包 2 和包 10 实机验收；提交成功不作为实际横幅出现的证据。

## 实施记录与发布门槛

每包记录范围、测试命令及结果、实机证据、迁移影响和回退方式；当前无 Git 时不得假装已有提交或 PR。

行为包先跑对应测试，再跑必要集成检查。发布候选执行 swift test、swift build -c release；签名、公证、Gatekeeper 与架构校验针对实际分发产物。测试跳过、无证书、无真实账号或无对应系统设备均记录为未验收，不以自动化通过代替。

公开测试前完成 A1 支持边界、A2 分发、B1/B2 安全恢复和 E 材料；C/D 首发范围按本拆分推进。D2 架构深化与 Mac App Store 保持后续独立项目。首次执行建议从包 1、包 2 开始，先获得可见改善并验证旧用户行为，再进入凭据迁移。
