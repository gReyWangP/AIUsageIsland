# 设置页与多平台排版（1.9.5）

**Goal:** 加设置页（屏幕选择、悬浮条方向、详情排版），并把"两个平台"的硬编码换成 N 平台 × M 排版。

## 为什么要先重构

旧版用一个 `dual: Bool` 同时表示三件事：有几个平台、用哪种排版、面板该多大。
这个 Bool 串在 25 个地方，而且正是「鼠标在卡片上却被判为离开」那个 bug 的根源——
判定区按 `bothConnected`、卡片按 `hasTwoColumns`，两者不一致就出问题。
加第三个平台或加排版选项会让它变成组合爆炸，所以先把结构改对。

## 四步

- [x] **设置模型**：`IslandSettings`，`UserDefaults` 持久化；`ScreenSelection` 存 ID + 名字双份。
- [x] **数据/排版分离**：新增 `PlatformSnapshot`，排版只消费快照。行数、指标数、账号信息都在这里，
      加平台 = 多产出一份快照，加排版 = 多写一个 View，两者正交。
- [x] **尺寸实测驱动**：`IslandView` 把悬浮条与详情的实测尺寸上报给 `presentation`，
      `NotchLayout` 退化成**锚点 + 触发策略**，不再计算尺寸。
      `compactFrame(dual:)` / `detailFrame(dual:)` / `detailHitRect(dual:)` / `shouldShow(dualDetail:dualCompact:)`
      全部删除——**判定区就是面板 frame，面板 frame 就是实测内容尺寸**，
      「判定区和卡片不一致」这类 bug 从结构上不可能再发生。
- [x] **新排版**：横向/纵向悬浮条、并列栏/堆叠详情。

## 已知取舍

- **纵向详情把说明文字移到悬停提示**。卡片结构（平台名 → hero → 指标 → 说明 → 刷新 → 分隔线 → 账号）
  一个字没动，但说明不再常驻。若希望它常驻，堆叠排版在 3 个平台时会超出 50% 上限并滚动。
- **横向悬浮条在 1 个平台时也牺牲刘海行**，比旧的翅膀式高 23 pt（64 → 87）。
  换来的是平台数从 2 增到 3 时高度完全不变。
- **设置页做成原地替换而非弹窗**：SwiftUI 的 `Menu` 在 `.nonactivatingPanel` 里完全不绘制
  （依赖 AppKit 菜单基础设施），`Popover` 同样不可靠。
