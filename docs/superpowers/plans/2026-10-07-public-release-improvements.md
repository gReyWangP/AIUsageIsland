# AIUsageIsland 公开发布改进计划

> 执行说明：这是基于 1.19.9 评估形成的产品与工程路线图，功能取舍均为建议。本轮仅形成计划，不修改产品行为。后续按独立任务使用 superpowers:executing-plans 细化并执行；涉及凭据、持久化与架构的任务应分别形成详细实现方案，不一次性混改。

**Goal:** 将现有功能完整的个人工具，整理成易理解、可恢复、可持续维护的公开产品。

**Architecture:** 保留 SwiftUI / AppKit、账号独立 AccountRuntime、平台适配器和统一数据快照。优先改善发布、安全与关键交互，再把存储和平台职责从主线程及运行协调层中分离；维持旧账号、设置和通知标识兼容。

**Tech Stack:** Swift 6、SwiftPM、macOS 14+、SwiftUI、AppKit、WebKit、AuthenticationServices、Security / Keychain、UserNotifications。

**Spec:** 2026-10-07 当前对话中的源码成熟度评估，以及本文的目标、约束和功能取舍。本文不代表已验证商店审核资格或真实平台全部可用。

## 目标、路径与证据

产品定位：Mac 顶部的 AI 账号用量速览工具。核心回答四件事：还有多少、何时恢复、哪个账号可用、数据是否最新。

路径选择：

| 路径 | 收益与代价 | 建议 |
| --- | --- | --- |
| 先做签名分发的公开测试，再推进稳定版 | 能较早验证不同设备和真实账号；需要明确测试版限制 | 推荐 |
| 直接冲 Mac App Store | 需要先完成沙盒、服务使用依据、审核材料等验证，周期不确定 | 作为独立分支评估 |
| 全面重构后发布 | 改动面大、回归来源多，会推迟真实反馈 | 不采用 |

分发渠道尚未由用户确定。主线暂按官网 / GitHub 下载设计，商店准备单列，不将签名公证等同于商店上架资格。

评估基线：2026-10-07 执行 swift test，418 项、2 项跳过、0 失败；跳过公共公告联网探测和需要显式匿名样本的真实日统计验收。当前 dist 二进制为 arm64、ad hoc 签名。当前目录没有 Git 元数据，不推断远程仓库状态。未完成新的真实多账号登录、设备兼容或能耗验收。

## Global Constraints

- 最低系统要求维持 macOS 14，不在本轮扩展移动端或 Windows。
- 不读取或迁移其他客户端的凭据；应用自己的账号与 WebKit 空间继续隔离。
- 不把缺失数据当成零，不把额度百分比换算成 Token，不把公告或倒计时结束当作额度已恢复。
- UI 可以合并入口，但余额、额度采样与官方日统计保持独立数据口径。
- 现有用户显式设置优先；新默认值通过版本化迁移引入，不能用统一覆盖覆盖旧选择。
- 不更改 bundle identifier、账号 UUID、通知标识或历史路径来完成品牌清理。
- 隐藏高级功能不删除配置；已有预约、提醒与历史仍可查看、编辑和清理。
- 先固定正式签名身份，再验收 Keychain 和升级迁移；凭据写入确认前不删旧文件。
- 暂停新增平台、聊天、模型推荐、统一账单和云同步。
- 只做本轮任务必要的测试；纯文案、字号和折叠布局用实际交互及渲染检查，避免测试复述实现。

## Review Focus

1. 新安装与升级默认值不同：首次使用任务验证新默认、旧偏好保留、迁移重复执行。
2. 钥匙串锁定、拒绝访问或轮换写入失败：凭据任务验证保留有效授权、正确报错和重试，不以空值冒充未登录。
3. 写盘未完成时移除账号：存储任务验证迟到任务不会重新创建已删除历史。
4. 同一请求遇到授权过期、429 和取消：恢复任务验证限流优先、请求不越权重试、不丢已轮换凭据。
5. 多屏切换、全屏、睡眠以及通知受系统抑制：发布验收验证入口可达、窗口不挡工作、无重复提醒，不将提交成功冒充用户已看到通知。

## 功能取舍

| 功能 | 决策 | 公开版表达与边界 |
| --- | --- | --- |
| 三平台、多账号、最多四个显示账号 | 保留 | 当前账号体系与显示限制不变，隐藏账号仍可用于状态栏或提醒 |
| 顶部浮窗、余额、剩余额度、重置时间 | 保留并突出 | 先显示剩余与更新时间；详细已用值保留明确标签 |
| 菜单栏 | 新安装默认开启 | 未登录也有入口；旧用户关闭的选择保留 |
| 首次引导 | 改为一次性引导 | 开始使用后记完成；手动关闭本次不强制完成；设置中可再次打开 |
| 额度趋势、用量分析 | 合并入口与窗口 | 一个“用量分析”，内部“消耗统计 / 额度变化”；保留各自来源、时间范围和缓存说明 |
| 低额度、实际恢复提醒 | 保留 | 账号层只突出两种主要提醒；无限或不适用的指标不给可用错觉 |
| 提醒时段、窗口选择、自定义阈值 | 高级化 | 总状态可见，细节折叠；通知阈值和图标颜色标准的差异继续说明 |
| 官方重置动态 | 改为“Codex 重置公告”，可选订阅 | 新用户默认开启（2026-10-07 用户调整）；明确第三方汇总来源，不能表示个人额度到账 |
| 到点预约、提醒事项集成 | 高级化 | 主动预约独立于自动额度提醒，明确何时仍会触发；不要求无关权限 |
| 显示组合 | 保留，降低首次存在感 | 两个以上账号或已有组合时突出入口；切换组合不改变凭据及提醒 |
| 横竖布局、圆环粗细、浮窗指标组合 | 保留在高级外观 | 基础页保留主题、显示位置和简洁布局预览；不删除旧配置 |
| 导入导出、匿名诊断 | 保留在“通用与支持” | 迁移文件不含凭据，不恢复系统权限或擅自开启登录项 |
| 详细渲染日志 | 正式版默认关闭 | 故障排查临时开启，设定保留上限；必要资源故障仍有轻量记录 |
| 更多平台、聊天、云同步、统一账单 | 本轮不做 | 稳定版验证完成后再单独评估 |

建议设置结构为“账号 / 外观 / 提醒 / 通用与支持”。账号页负责身份、连接状态、显示与状态栏目标；外观页负责布局和样式；提醒页负责生效状态与规则；通用与支持负责启动、快捷键、配置、诊断、版本、隐私和反馈。用量分析仍作为独立工具窗口入口。

## 阶段 A：确定公开发布边界（P0）

### A1. 平台接入与产品承诺

**涉及文件：** ChatGPTAuthFlow.swift、ChatGPTAccountClient.swift、PlatformAccountClient.swift、ZhipuWebSession.swift、UsagePlatform.swift、README.md、docs/LogoSources.md。

- [ ] 整理三平台能力表：授权路径、请求来源、数据范围、已验证套餐、不能提供的字段和恢复入口。
- [ ] 对 ChatGPT 复用 Codex OAuth 客户端和后端接口的做法核实服务使用依据；区分可访问、真实可用、长期支持三个结论。
- [ ] 对智谱网页变化、身份延迟、验证码及会话失效列出支持边界；不绕过平台安全验证。
- [ ] 所有对外文案将 ChatGPT 的 Codex 额度与聊天用量区分；公告来源与账号额度来源分别说明。
- [ ] 为每个平台确定接口异常时的降级：保留最近有效数据、标明过期、提供官方页面和恢复操作。

**完成标准：** 每个平台都有可说明的数据范围和已验证状态；无法核实的部分明确标注限制。若某平台不适合对外提供，不将其宣传为稳定支持；保留已有用户数据，不静默删除账号。

### A2. 分发基线

**涉及文件：** scripts/build-app.sh、Info.plist、Package.swift、releases/README.md；新增发布校验脚本和发布说明。

- [ ] 明确首发为 Apple Silicon；如要支持 Intel，另建 x86_64 构建与实机验收，不仅修改下载文案。
- [ ] 将开发临时签名与正式发布分开；正式模式缺少证书、公证结果或必要资源时直接失败。
- [ ] 固定 Developer ID 身份，启用所需 Hardened Runtime 配置，接入公证和票据装订。
- [ ] 版本以 Info.plist 为依据；移除网络 User-Agent 等位置的陈旧硬编码版本。
- [ ] 确认真实源码仓库与构建环境后配置 CI：测试、Release 构建、资源与版本检查；证书和公证凭据只使用受控密钥配置。
- [ ] 在干净用户环境从真实下载产物完成安装，验证 Gatekeeper、应用启动和替换升级。

**验证命令：** swift test；swift build -c release；codesign --verify --strict；spctl --assess --type execute；xcrun stapler validate；file 检查发布架构。最后三项对实际签名分发产物执行。

**完成标准：** 一个下载链接对应一个可追溯版本；用户不依赖终端绕过系统安全检查安装；发布页标明系统和架构范围。

## 阶段 B：安全与异常恢复（P0）

### B1. 凭据存储迁移

**涉及文件：** SessionStore.swift、ChatGPTUsageAdapter.swift、AccountRuntime.swift、IslandModel+Accounts.swift；新增独立 Keychain 存储实现及迁移测试。

- [ ] 先定义存储错误分类：不存在、权限/锁定、内容损坏、读写失败；避免把读取失败统一显示为未登录。
- [ ] Keychain 条目以应用、平台、账号 UUID 隔离；限制为本机，不启用 iCloud 同步。
- [ ] 迁移顺序为读取旧凭据、写入 Keychain、读回验证、删除旧文件、记录完成；任一步失败都可重试且不重复创建账号。
- [ ] 轮换令牌保存失败时阻止无效重试并给出恢复说明；不能为了回滚恢复已被服务端废弃的 refresh token。
- [ ] 删除账号同时处理凭据和对应 WebKit 数据；删除失败不宣称已完成。
- [ ] 验证签名开发版到正式版的迁移、正式版覆盖升级、钥匙串锁定和用户拒绝访问。

**测试重点：** 用可注入存储模拟写入/读回/删除失败；真实 Keychain 验收使用测试条目和正式签名产物，不读取其他软件凭据。

**完成标准：** 已迁移账号不再依赖明文授权文件；失败不丢唯一有效凭据。由于旧二进制无法读取新存储，回退策略应是使用兼容新存储的修复版或重新授权，不能承诺旧版直接无损回退。

### B2. 异常状态和恢复动作

**涉及文件：** AccountReminderSettings.swift、AccountSettingsView.swift、UsageRefreshFailure.swift、RefreshPolicy.swift、AccountRuntime.swift、Diagnostics.swift。

- [ ] 保留现有结构化错误分类，账号行进一步区分授权失效、离线、限流、接口变化与等待首次更新。
- [ ] 提供对应动作：重新登录、重试、等待冷却、打开官方用量页；网络失败不引导用户反复重新登录。
- [ ] 清除依靠错误字符串前缀判断重复账号的分支，改用结构化账号管理状态。
- [ ] 诊断补充额度刷新与日统计各自的状态；不包含账号名称、Token、Cookie、响应正文或身份 ID。
- [ ] 回归现有授权并发、账号隔离、刷新退避和取消路径；只为新增状态转换补测试。

**完成标准：** 用户从账号行能知道下一步，两个数据接口不再以一个含糊状态相互掩盖。

## 阶段 C：公开版体验收敛（P1）

### C1. 首次使用和普通窗口

**涉及文件：** IslandSettings.swift、IslandGuide.swift、main.swift、MenuBarStatus.swift、UsageAnalysisView.swift。

- [ ] 新安装默认显示菜单栏入口；旧用户显式关闭保持关闭。迁移标记区分已有安装与全新安装，遇到无法识别的旧状态保守保留原行为。
- [ ] 开始使用后保存引导完成状态；已有账号用户升级不重复弹出引导；设置入口始终可手动打开。
- [ ] 用量分析改为普通窗口层级与普通桌面行为；顶部浮窗继续原有职责。
- [ ] 检查小屏可用高度，必要时滚动或缩小最小尺寸，保证关闭、账号选择及分析操作可达。

**验收：** 全新启动、未登录、已有账号升级、菜单栏关闭、引导再次打开、多桌面切换分别走通；分析窗口不遮挡其他普通工作窗口。

### C2. 合并历史入口

**涉及文件：** AccountSettingsView.swift、UsageAnalysisView.swift、UsageTrendView.swift、IslandSettingsView.swift、UsageOverviewRow 所在文件。

- [ ] 统一“用量分析”窗口和账号选择；内部切换“消耗统计 / 额度变化”。
- [ ] 今日消耗入口打开消耗统计；旧额度趋势入口过渡为打开同一窗口的额度变化页。
- [ ] 两页共用账号上下文，但分别保留 7/30 天官方日统计与 24 小时/7 天本地采样范围。
- [ ] 无统计权限、无限额度、历史不足时分别给出空态；不为填满图表制造数据。

**验收：** 切换账号与页签无串号；单纯切换已缓存的页签不额外发请求；两种数据来源、缓存状态和更新时刻清楚可见；移除当前账号后能选择其他账号。

### C3. 设置与提醒收敛

**涉及文件：** IslandSettingsView.swift、UtilitySettingsView.swift、AccountAlertSettingsView.swift、ReminderSettingsView.swift、OfficialResetSettingsView.swift、DisplayPresetSettingsView.swift、SettingsTransfer.swift。

- [ ] 调整为账号、外观、提醒、通用与支持四个分组；移动入口不改变底层偏好标识。
- [ ] 总暂停状态固定显示在提醒页顶部；账号默认突出低额度与实际恢复两项，其他规则折叠。
- [ ] 明确自动额度提醒、公告订阅、手动预约的作用范围，暂停后哪些预约仍有效直接展示。
- [ ] 新用户公告订阅默认开启；旧用户现有偏好保留。关闭订阅不后台请求公告，不抹去已有主动预约。
- [ ] 显示组合和外观细项进入高级区；已有组合仍可访问，保持导入导出兼容。
- [ ] 设置页采用系统文字样式或更易读的字号/对比度；完成键盘焦点、VoiceOver、浅深色和减少透明度检查。

**验收：** 无需展开高级区即可添加账号、选择显示、开启简单提醒；用户能直接识别提醒是否生效及原因；升级前后配置与已预约事项保持一致。

## 阶段 D：常驻质量和维护性（P1 / P2）

### D1. 日志、持久化与能耗（P1）

**涉及文件：** RenderStateLog.swift、IslandView.swift、IslandBrand.swift、UsageTrend.swift、UsageAnalysis.swift、main.swift；新增串行历史存储组件及生命周期测试。

- [ ] 正式版关闭详细渲染文件日志，保留轻量异常记录和有上限的显式诊断模式。
- [ ] 主线程只更新展示快照；编码、读取、写盘进入串行存储执行器，同次刷新多个指标合并写入。
- [ ] 存储按账号保序；删除时取消或失效化排队任务，防止迟到写入重建目录。
- [ ] 为写入失败保留可见状态和内存数据；退出前采用有界等待或明确的未落盘策略，不无限阻塞退出。
- [ ] 建立空闲、悬停、四账号、分析窗口、睡眠恢复五种状态的 CPU、内存、磁盘和唤醒基准，再决定鼠标检测频率是否调整。

**验收：** 慢磁盘不阻塞 UI；账号删除后迟到任务无法复活历史；长时间重复开关窗口不持续增长内存。性能优化须有同环境前后数据；本轮不编造未测量的性能目标。

### D2. 运行层边界（P2，稳定发布后或新增平台前）

**涉及文件：** AccountRuntime.swift、AccountRuntime+Snapshot.swift、IslandModel+Compatibility.swift、三个平台适配器。

- [ ] 从调用点梳理兼容入口，先迁移仍在使用的调用点，再删除已无使用者的转发。
- [ ] 逐个平台收拢专属状态、认证和刷新逻辑；AccountRuntime 保留账号生命周期、调度和统一快照协调。
- [ ] 每次只迁移一个平台，维持既有存储和快照语义，跑对应隔离与竞态测试。
- [ ] 不新增通用插件框架，不要求为了文件长度拆分所有视图。

**验收：** 账号切换、删除、授权取消、令牌轮换和隐藏账号提醒行为不变；新平台无需向一个类增加整套无关平台字段。

## 阶段 E：发布材料与真实验收（P0 发布门槛）

**涉及文件：** README.md、releases/README.md、docs/LogoSources.md；新增 CHANGELOG.md、隐私说明、发布验收记录。若分享源码，选定并加入 LICENSE。

- [ ] README 改为用途、截图、支持范围、安装、隐私、限制和反馈；历史修复记录移到 CHANGELOG。
- [ ] 应用内加入关于、隐私、反馈和版本说明入口；先提供手动访问下载页的更新路径，完整自动更新另行评估。
- [ ] 隐私说明覆盖凭据、WebKit 数据、用量历史、公告请求、保留范围和删除方式；不以“数据在本机”省略外部请求说明。
- [ ] 记录平台图标来源与使用依据；明确独立第三方工具身份。
- [ ] 全量自动化通过后，用发布产物执行真实验收：干净安装、覆盖升级、授权过期、多账号、断网/限流、睡眠、多屏/全屏、通知允许/拒绝/系统抑制。
- [ ] 每个承诺支持的平台至少完成真实账号验证；每个承诺支持的系统大版本记录实际验证结果。真实账号样本匿名化后才能进入测试资源。
- [ ] 邀请少量外部用户进行 1–2 周公开测试观察，记录问题与修复版本；时间是观察建议，不是上线承诺。

**稳定版门槛：** 无已知账号串用、凭据丢失、启动崩溃和静默误报；安装升级闭环通过；关键外部测试不以跳过算通过；文档与实测范围一致。系统通知受专注/共享等抑制应准确解释，不能承诺应用绕过系统策略。

- [ ] 验证沙盒 entitlement 与本地 OAuth 监听、WebKit 数据目录、快捷键、登录项、提醒事项和用户选择文件读写。

## 执行顺序与拆包

1. A1 明确支持边界，同时准备 A2 正式签名身份与 E 发布材料。
2. 独立变更完成 C1 窗口与首次使用、B2 异常恢复；这些不依赖大重构。
3. 在签名身份固定后独立完成 B1 凭据迁移，验收后再并入发布候选。
4. 分别完成 C2 历史入口、C3 设置提醒；每个变更都可单独验证和撤销布局调整。
5. 完成 D1 日志与存储优化，跑集成回归；不要与凭据迁移同时重写。
6. 完成 A2 下载产物验收和 E 外部测试，问题清零后发布稳定版。
7. D2 架构深化与商店分支单独推进，不作为官网首发的无条件前置。

每个变更包记录范围、验证证据、迁移影响和回退方法。可逆 UI 调整通过代码回退；凭据迁移只回退到兼容新存储的版本。界面收敛先隐藏、合并入口，至少保留一个过渡版本的旧配置读取能力。
