# 双平台详情卡重构（1.9.4）

> **For agentic workers:** 详情页高度常量与 `DetailLayoutTests` 的实测值绑定，改行高必须同步。

**Goal:** 消除双平台详情里「外轮廓整齐、内部逐行错位」的问题，并把详情面板高度从 480 pt 降到由内容推导。

## 问题

旧版两列是两个各自独立的 `VStack` 顶端对齐堆叠，外面套一对等高的 `RoundedRectangle` 背景：

- 背景承诺了对称，但内部**没有任何共享的行网格**。左列 5 个视觉带、右列 3 个，中间整段对不上。
- 两列内容高度实测约 301 pt，而可用 340 pt → **39 pt 是纯空白**。
- 分隔线与账号区随内容长短漂移，差 5 pt；一旦某侧多一行错误提示就拉到 18–25 pt。
- 同一张卡片语言不统一：药丸圆角 7 / 内边距 6×7，额度卡圆角 10 / 内边距 10。
- 「今日 Token」在一行里以 8 pt 副值出现过，下面又以 11 pt 裸行重复出现。
- 智谱额度卡同时显示「已用 42%」和「剩余 58%」，后者是前者的补数，冗余。

## 改动

- [x] 新增 `IslandDetailGrid`：两列放进**同一个** `Grid`，每行高度取两列最大值 → 基线天然对齐。
- [x] 两个 hero 改为完全同构（标签 + 30 pt 数字）。**去掉智谱 hero 的进度条**——它让该列比另一列高 12 pt，底部对齐时把标签和数字整体顶高，两列 hero 差 12 pt。
- [x] 列标题也纳入 Grid，与 hero 之间有正常的行间距（否则标签会紧贴列标题）。
- [x] 删除「剩余 %」及 `ZhipuQuota.Window.remainingPercent`（已无引用、无测试覆盖）。
- [x] 删除 DeepSeek 列里重复的「今日 Token」裸行。
- [x] 新增 `UsageFormat`，把金额／百分比／重置时间格式化收敛到一处，两列共用。
- [x] 详情高度改为 `内容 + topInset + 框架开销`，刘海屏 440 pt、外接屏 413 pt，**两者内容可用高度一致**（旧版写死 480，外接屏会多出 27 pt 空白）。
- [x] 新增 `DetailLayoutTests`：用 `ImageRenderer` 实测内容高度，并逐像素校验两列上下边界齐平。

## 1.9.4 实机反馈修复

首次实机运行暴露了四个问题，其中前两个同源：

1. **鼠标还在卡片上却判为离开。** 卡片尺寸由 `hasTwoColumns`（两个平台**已启用**）决定，
   判定区却由 `bothConnected`（两个平台**都已登录**）决定。启用两个但只登录成功一个时，
   卡片 565×413、判定区只有 360×360，靠边即误判。
   → `shouldShow` 拆成独立的 `dualDetail` / `dualCompact` 两个标志，
   并加了 `testDetailHitRectCoversWholeCard` 锁住「判定区必须与卡片完全重合」。
2. **高度不够、内容滚动。** 同一个错配让面板按单平台算高度；而且未登录（内容 364 pt）、
   接口报错（332 pt）都高于正常态（317 pt），写死高度必然滚动。
   → 高度改为运行时自适应：`IslandDetailGrid` 用 `GeometryReader` 上报实测高度，
   `AppDelegate` 订阅 `presentation.$detailContentHeight` 重设面板。
   `dualContentHeight` 降级为下限。
3. **移出后消失太快。** 阈值 0.18 s → `AppDelegate.hideDelay`（先取 1.0 s，实测偏黏滞后定为 0.5 s）。
4. **行卡片文字贴着左边框。** `cellLayout()` 的 10 pt 是列内边距（卡片外），
   卡片还缺一层自己的内边距。
   → 新增 `IslandDetailGrid.cardPadding = 10`，两层留白分开。

## 1.9.4 第二轮：移除平台的下放

- 移除操作原先藏在账号区里、且只在「未登录」时才出现，导致看起来「只有智谱有」。
- 改为详情左下角一个 ⊖ 图标：`.help("移除平台")`，点开浮出平台列表，
  列出 `PlatformAccounts.ordered`（按 `allCases` 固定顺序，`Set` 本身无序）。
- 任意平台都可单独移除；移除最后一个后回到平台选择页，标题规则保持
  「1 个 → 平台名，2 个 → 用量统计，0 个 → 选择平台」不变。
- 账号区与单平台视图里的旧按钮一并删除，避免两处入口。

### 两个实机踩到的坑

1. **SwiftUI `Menu` 在 `.nonactivatingPanel` 里完全不绘制。** 实测左下角一片空白；
   `ImageRenderer` 里它也被画成占位符——因为它依赖 AppKit 的菜单基础设施。
   改用纯 SwiftUI 的 `overlay` 浮层列表，完全可控，也不受面板激活状态影响。
2. **`onChange(of: mode)` 不能无条件复位浮层。** 展开动作本身就会把刚打开的列表关掉；
   改为只在 `newMode == .hidden` 时复位。

> 这两个都是靠 `screencapture` 截真实面板发现的，单元测试与 `ImageRenderer` 都覆盖不到。

## 已知取舍

- 智谱只有 2 个额度窗口而 DeepSeek 有 3 个时段，为对齐行数，智谱的第 2、3 行放重置时间。信息量比左侧轻，但比留空或塞占位字段更诚实。
- 详情页现在没有任何进度条。若之后需要，可在指标行下方垫 2 pt 发丝线，不占行高、不影响 hero 对齐。
- 错误态内容会超过面板高度并触发滚动，这是 `ScrollView` 的预期职责。
