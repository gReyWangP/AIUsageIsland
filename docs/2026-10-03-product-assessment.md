# AIUsageIsland 产品与技术评估

评估日期：2026-10-03。范围：当前源码、README、最近完成的多账号与引导优化；没有重新登录真实账号，没有修改产品行为。

> 后续实现说明（2026-10-04）：本文是评估时点的记录，多账号独立提醒已在后续代码实现；账号运行模型现已提取为固定 AccountRuntime，不再递归创建 IslandModel。当前变更与验证以 `superpowers/plans/2026-10-03-account-runtime.md` 为准，以下建议不能直接视为当前缺陷清单。

## 定位与现状

建议定位为「Mac 上的 AI 账号用量速览工具」：快速回答哪个账号还有额度、什么时候重置、数据是否可信。

当前已具备：DeepSeek／智谱 CodingPlan／ChatGPT 接入；同平台多账号及自定义名称；最多四个显示账号；悬浮横向／纵向和明细并排／堆叠；单个菜单栏图标选择具体账号；刷新、缓存与错误提示；低额度、实际恢复和到点预约提醒；官方公告；主题、多屏、全屏策略、快捷键与登录项；一页快速引导。

优势是查看路径短、原生界面、凭据留在本机、多账号状态已做隔离。SwiftPM 包没有第三方依赖。当前功能广度已足够，下一阶段宜优先完善数据表达和账号体验。

## 可拓展方向

1. **本地额度趋势**：按账号记录有效额度快照，先提供最近 24 小时与七天曲线。需要记录窗口标识、重置时间和数据间隔；窗口滚动、额度补发或采样缺口不能解释为消费。可报告两次有效采样间额度下降，不能推导精确 Token 或剩余请求次数。
2. **账号显示组合**：保存「工作」「个人」「编程」等预设，一键替换最多四个显示账号。菜单栏账号和提醒策略是否随组合变化应可明确选择，避免切换布局时悄悄改变提醒。
3. **官方用量页入口**：卡片提供打开对应平台用量页，便于对照。这是低成本、较直接的体验补充。
4. **更多平台**：先做接入可行性验证，再承诺支持。必须区分订阅额度、API 账单、组织统计和本机估算。例如 Claude 的官方 Usage & Cost API 面向组织 API 用量，并不能直接作为个人订阅额度接口使用。
5. **设置导入导出**：迁移布局、显示顺序、快捷键及提醒设置。凭据默认不纳入导出；跨机器后通过重新登录关联账号。

不建议目前同时扩大为聊天工具、模型推荐器或跨平台统一账单系统；这些会引入另一套交互和不一致的数据口径。

## 技术维护

- **逐步拆分账号运行状态**：当前非当前账号复用完整 `IslandModel` 作为运行实例；主模型约 957 行，还承担认证、平台刷新、状态与账号管理。新增平台前宜提取账号运行状态与平台适配层，UI 继续消费统一快照；不需要一次性全面重写。
- **认证并发保护**：已有进程内刷新状态、请求版本和账号隔离。此次查看的入口与存储代码未见应用级单实例或跨进程令牌刷新锁；开发版与安装版同时运行并共享目录时，可能竞争更新轮换令牌。需要独立复现并验证，再选择单实例唤醒或跨进程保护，不能据此宣布已发生故障。
- **接口失败策略**：普通刷新约五分钟、自动请求至少间隔三十秒，官方公告另有退避。可为账号接口补充按错误类型退避、429 响应处理和平台级并发上限；是否调整成功刷新频率，应以数据变化和请求成本测量决定。
- **减少常驻诊断成本**：渲染状态变化会写文件、修剪日志并输出系统日志。建议提供可开关诊断模式或使用系统日志，先测量开销再决定调整；本次没有做 CPU／内存／能耗基准，不能断言性能存在问题。
- **正式分发**：打包脚本当前使用 ad hoc 签名。若向其他用户长期分发，应考虑 Developer ID 签名与公证，再讨论升级检查及钥匙串迁移。此前暂不实施签名和应用内更新的决定，本次评估没有改变。

## 建议顺序

第一阶段：数据口径说明、账号状态、账号用途摘要和提醒目标明确化。

第二阶段：诊断入口、接口失效恢复、显示组合、本地趋势。

第三阶段：平台适配层、经验证的新平台、面向他人的正式分发。
